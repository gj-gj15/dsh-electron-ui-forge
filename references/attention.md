# 注意力导演

> 这一份是**设计原理 + 实现要点**。数值来源与调参边界见 `visual-recipe.md`，
> 可移植代码是 `../assets/attention-core.js`，回归测试是 `../scripts/selftest.js`。

一句话：**同一时刻，屏幕上只有一个区域占 100% 权重，其余区域主动退让。**

界面吵，往往不是因为元素多，而是因为所有元素都在用同样的音量说话。注意力导演做的
不是减法（删掉东西），而是**分配权重**：按人此刻在做什么，把权重集中到一处。

## 何时用

- 对话界面里，用户不知道该看输出还是看输入框
- 生成过程中整页都在动，看不出哪里是「正在发生的事」
- 想让输入框有「被拿起来」的手感
- 需要给界面加焦点感，但不想改造配色、换字体、重排版

不适用：静态展示页（没有状态循环）；信息密度本身就是目的的后台面板。

## 核心原则

1. **只调权重，不改身份。** 只碰 `opacity` / `filter` / `transform` / `box-shadow`，
   不动底色、字体、字号、布局。用户装的主题说了算，导演只决定谁大声。
2. **单一事实来源。** 状态从宿主 DOM 推导，不自己维护一套并行状态。
   宿主是唯一真相，插件只做翻译。
3. **状态全自动。** 不放额外开关按钮。开关会打断循环，而循环本来就是为了不打断人。
4. **撤销靠事件，不靠计时。** 计时器猜不准「人什么时候读完」。
5. **宁可不压，不要误压。** 压暗的前提是焦点就在眼前。焦点不在视野里时，
   满屏退让变成纯粹的惩罚。

## 状态机

| 态 | 触发条件（按优先级从高到低） | 焦点 | 其余 |
|---|---|---|---|
| `approval` | DOM 里出现「等你回话」的卡片 | 卡片本身 | 0.46，输入区保持 1 |
| `running` | 存在 `[data-state="running"]` 的块 | 最新运行块 | **0.36** |
| `typing` | 光标在输入框里 | 输入卡 | 0.55 |
| `done` | 刚出完结果且结果仍在视野 | 结果块 | **0.42** |
| `idle` | 以上都不成立 | — | 1.0 |

优先级即上表顺序，`derive()` 从上往下第一个命中的就是当前态。

### `approval`：一切「等你回话」的卡片

定义只有一条：**只要屏幕上出现一块「必须先回应它才能继续」的 UI，它就是焦点。**

它压过 `running`，因为此刻 AI 在等用户，不在等自己。三种形态都属于这里：

| 形态 | dsh 里的锚点 |
|---|---|
| 工具执行前的许可 | `[data-approval-key]` |
| AI 提问、给选项让用户挑 | `[data-question-key]` |
| 计划提交上来等批准 | `[data-plan-review-key]` |

已答完的历史记录（`[data-question-reply]`）不在其中——那是消息流里的旧内容，
该跟着 `running` / `done` 的规则退让。

**两个实现陷阱，都会让这个态反向工作：**

1. **输入区不能压。** 这类面板通常做成「接管输入框」：挂在输入卡的 overlay 锚点里
   （dsh 是 `[data-composer-overlay]`，`height:0; position:absolute`），是输入卡的
   **后代**。如果退让规则里写了「输入区降到 0.6」，被压暗的正是焦点自己——
   用户要做的选择是半透明的。正确做法：消息流退到 0.46，输入区保持 1。
2. **别用别人的 slot 名去猜。** dsh 里 `[data-slot*="approval"]` 一次都不会命中：
   slot 全集里没有 approval，真正渲染这些面板的是组件自建的 `data-*-key` 属性。
   判据要么来自实测 DOM，要么来自组件源码，不能凭语义猜。

**离开条件**靠事件：用户点了选项 / 批准 / 拒绝后卡片消失，自动落回 `running`
（AI 接着干活）或 `done`。不要用计时器撤。

### `running` 的时间窗：从「提出问题」到「答案开始」

`running` 不是「AI 正在干活」的同义词，它有明确的起止：

| 边界 | 判据 | 屏幕上的表现 |
|---|---|---|
| **起点** | 用户按下发送、问题进入 DOM | 输入卡缩回，正在处理的那一块成为唯一焦点，其余压到 0.36 |
| 中间 | 排队、思考、调工具、等首字 | 全程算 `running`——这段时间屏幕上唯一在动的就是那一块 |
| **终点** | 答案出现（不再有「正在处理」的标记） | 焦点转到答案本身，周围放松到 0.42（`done`） |

**关键区分**：`typing` 在按下发送的那一刻就该结束，不能因为光标还留在输入框里而继续。

这是实现上最容易滑出去的地方。多数宿主的输入框发完消息后**焦点不离开**，
如果 `typing` 的判据只是「`activeElement` 在输入卡里」，那么提问后的整个等待期
都会停在 `typing`：输入框保持放大发光、迟迟不缩回，与「发出指令后输入框缩回」正好相反。

正确判据要再收一层——焦点在框里 **且** 用户确实在写（有内容，或刚打过字）：

```js
if (inputFocused() && !justSubmitted) return 'typing'
```

`justSubmitted` 在按下发送时置真，用户下次输入或重新点进输入框时置假。

另一半陷阱在宿主侧：`data-state="running"` 常常一直挂到整轮结束才移除。
直接把「存在 running 标记」当判据，用户读答案的全程周围都压着，`done` 可能永远不出现。
判据要能区分「在等」和「在答」。

**为什么 running 比 done 压得更狠**（0.36 < 0.42）：生成中是「别看我还在做别的」，
出结果后是「看这个，但周围也别太黑」。压得太狠，用户会觉得整页在闪。

**为什么 typing 最松**（0.55）：用户此刻还要能扫到上文里自己引用的那段。

### `done` 不能算出来，只能记下来

DOM 上没有「刚刚结束」这个标记。它只在 `running` 消失的那一刻存在，且只存在一瞬间。
所以必须记：

```js
if (hasRunning()) {
  sawRunning = true
  doneActive = false
} else if (sawRunning) {
  sawRunning = false
  doneActive = true      // 这一轮结束，结果成为焦点
}
```

`done` 的撤销同样靠事件，两条：

- 用户开始输入（`typing` 优先级更高，自动接管）
- 结果块滚出视野（用户开始翻历史了，见下）

### 焦点块不可见时，全体恢复等权

```css
html[data-attn="running"][data-attn-offscreen] [data-flow]{ opacity: 1 }
html[data-attn="done"][data-attn-offscreen]    [data-flow]{ opacity: 1 }
```

判断：焦点块的 `rect.bottom > 0 && rect.top < innerHeight`。不可见时给根元素打上
`data-attn-offscreen`，压暗规则整体让位。

这一条是从用户视角反推出来的：他在往上翻历史、生成发生在屏幕之外，此时压暗
等于惩罚——满屏旧内容糊成一片，新内容又看不见。

### 错误行永不压暗

错误信息不属于「历史噪音」，用户必须看到。这条规则的**特异性要够**，
否则会被主规则压回去：

```css
html[data-attn="running"] [data-flow="error"]:not([data-attn-live]){ opacity: 1 }
```

`:not([data-attn-live])` 不能省——主规则带了这个选择器，不加就连不上同等特异性。

## 视觉配方

### 输入框：三样一起给才叫「被拿起来」

```css
html[data-attn="typing"] .composer-card{
  transform: translateY(-6px) scale(1.022);
  transform-origin: 50% 100%;       /* 从底边长，不顶下面的内容 */
  box-shadow:
    0 0 0 2px  rgba(166,124,0,.66),   /* 1px → 2px 实边 */
    0 0 0 7px  rgba(166,124,0,.09),   /* 贴边淡环，让边缘发虚 */
    0 0 30px 7px rgba(166,124,0,.20), /* 外发光 */
    0 18px 42px -12px rgba(43,38,32,.28); /* 离地投影 */
  transition: transform 260ms cubic-bezier(.22,1,.36,1),
              box-shadow 260ms cubic-bezier(.22,1,.36,1);
}
```

四条阴影缺一不可：没有淡环，边缘是硬的；没有投影，还贴在纸上没抬起来。
放大用 `transform` 不用宽高——改宽高会触发重排，整页跳一下。

**发光用品牌色或高饱和色，不用正文色。** 正文色（墨青、灰黑）和纸底明度太接近，
扩散出去只是一层灰，看不见「光」。

### 画面虚化：只在真的在打字时

```css
html[data-attn="typing"][data-attn-filled] [data-flow]{
  filter: blur(1.4px);
  opacity: .5;
}
```

两个条件同时满足才糊：状态是 `typing` **且** 框里有字。光标刚点进去就糊掉整页太凶
（点进去只是想看看），开始写了才该让位。

`1.4px` 是上限。再高一点，16px 的中文就糊成色块，看着像渲染故障而不是失焦。

### 过渡

统一 220ms `cubic-bezier(.4,0,.2,1)`，和宿主的动效节奏走。同时提供
`@media (prefers-reduced-motion: reduce)` 关掉。

## 实现步骤

### 1. 找锚点，别找类名

需要四类锚点：输入框、输入卡、消息块（带「运行中」标记）、审批卡。
用 `data-*` 属性定位，不用哈希类名。宿主没有合适属性时，自己注入一个当落脚点。

### 2. 状态写到根元素

```js
root.setAttribute('data-attn', state)      // idle | typing | running | done | approval
root.setAttribute('data-attn-filled', '')  // 输入框有字
root.setAttribute('data-attn-offscreen','')// 焦点块不在视野
```

CSS 全部挂 `html[data-attn]` 下。属性不在时对页面零影响——这是「可随时关掉」的技术保证。

### 3. 焦点打标

每轮把 `data-attn-live` 从旧焦点摘掉、打到新焦点上。CSS 用
`:not([data-attn-live])` 表达「退让」，比给每个非焦点元素单独写规则稳得多。

**必须过滤零高度节点**：宿主 DOM 里常有与正文同名、高度为 0 的测量 / 无障碍副本，
焦点给到那种节点等于给到空气。

```js
if (el.getBoundingClientRect().height <= 0) continue
```

### 4. 驱动方式

`MutationObserver` + 60ms 防抖，再加三个监听：

| 事件 | 为什么必须单独听 |
|---|---|
| `input` / `focusin` / `focusout` | 输入框的值变化不触发 MutationObserver |
| `scroll`（capture） | 焦点块是否滚出视口，DOM 上没有任何变化 |
| `attributeFilter` 只列关心的属性 | 不过滤会被主题脚本的样式回写触发，无限自激 |

`scroll` 必须 `capture: true`：滚动发生在内部容器上，不冒泡到 `window`。

### 5. 验收

用调试接口强制各态跑一遍（只影响本次会话，界面不落任何开关）：

```js
__attn.force('done')   // 逐态检查
__attn.auto()
```

三个判据：

1. 五个状态都能进入，且互斥
2. 任一时刻**有且只有一个** `[data-attn-live]`
3. `idle` 态下所有块的 `opacity` 都是 1

## 反模式

| 反模式 | 后果 |
|---|---|
| typing 时把卡片提亮一档 | 卡面变白、输入井仍是原色，多出一块色差补丁。**只靠描边和光晕说话** |
| 基础态规则写在状态规则之后 | 同特异性下后者胜出，「归零」会把状态效果吃掉。典型症状：光晕在、缩放永远 `matrix(1,0,0,1,0,0)`。**基础态必须写在前面** |
| 写无状态的 `[data-attn-live]{opacity:1}` | 会让 typing / approval 态也留下一块 100% 的旧消息，破坏单焦点 |
| 用 `setTimeout` 撤销 done | 读到一半突然变暗，跳变比压暗本身更难看 |
| 焦点块在屏幕外仍继续压暗 | 满屏旧内容糊成一片，新内容又看不见 |
| 把错误行一起压暗 | 用户会错过必须看到的信息 |
| 改 `width` / `height` 做放大 | 触发重排，整页跳一下 |
| 用计时器轮询状态 | 浪费帧，且必然有一帧的错位 |
| 拼接核心库时不加分号 | 末尾是赋值表达式，后接 `(` 会被 ASI 解析成函数调用。核心库末尾已补分号，但拼接时仍建议再加一道 `;` |

  冷启动探锚点）、`dsh-map.md`（真实锚点、变量族）、`startup-perf.md`（启动耗时诊断）

本方案不依赖任何特定宿主的源码。`attention-core.js` 只认 `SELECTORS` 里那几个属性，
把它挂到别的对话界面上，改配置对象即可——这也是为什么仓库里没有一份「完整插件示例」：
示例会过期，配置才是契约。
